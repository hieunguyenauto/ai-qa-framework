# 2026-10-14 Script-generated TCs share one flow for every branch and miss web steps
- Type: DESIGN_GAP
- Source: an E2E suite (production project, rev 2 LOCKED) generated by a script from a CSV
- Function / screen: request creation wizard (step 1 shop → step 2 item selection)
- Symptom: recon for automation showed (1) one category (feature flag OFF) uses the normal web flow without the embedded webview, but the TC said "Verify: webview opens"; (2) the TC starts at "choose category" — on the web app, step 1 (shop and person in charge → '次へ') comes first; the webview is inside an iframe.
- Second occurrence (rev 4, automation failure): a status step wrote "Verify: 'Pending'" for every quote; a quote at or below the limit is approved immediately.
- Root cause: the generator applied one template to every case and did not split branches by category / amount; the flow came from a CSV describing the mobile app, so the web wizard step was missing.
- Fix: rev 3 — each branch (webview / normal) has its own steps, step 1 added for every role. Rev 4 — the status after submit depends on the branch (≤ limit → 'Approved', > limit → 'Pending').
- Rule: D17 — flows taken from a CSV / mobile app are compared with the web screens (catalog or recon) before LOCK; every condition branch has its own steps and expected state, never one shared template. Related: D14.
- Applies to: E2E TCs imported from outside files, TCs generated in bulk by scripts / templates.
